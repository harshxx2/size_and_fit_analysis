# Validation Report

## Purpose
This document verifies that the analytical outputs generated by the **Python pipeline** (`src/analysis.py`) are consistent with the results obtained directly from the **SQLite database** (`data/processed/fit_feedback.db`). The goal is to ensure data integrity across tools before the final case study is presented.

## Validation Steps
1. **Load Data via Python (pandas)**
   ```python
   import pandas as pd
   df_py = pd.read_csv('../data/processed/renttherunway_cleaned.csv')
   ```
2. **Load Data via SQLite**
   ```python
   import sqlite3
   conn = sqlite3.connect('../data/processed/fit_feedback.db')
   df_sql = pd.read_sql_query('SELECT * FROM fit_feedback', conn)
   ```
3. **Row Count Equality**
   - Python DataFrame rows: `len(df_py) = 192,544`
   - SQLite table rows: `SELECT COUNT(*) FROM fit_feedback` = **192,544**
   - ✅ Match.
4. **Fit Distribution**
   - Python:
     ```python
     df_py['fit'].value_counts(normalize=True)
     ```
     Result: `fit` 73.78 %, `small` 13.39 %, `large` 12.83 %.
   - SQLite:
     ```sql
     SELECT fit, COUNT(*)*1.0/ (SELECT COUNT(*) FROM fit_feedback) AS pct
     FROM fit_feedback GROUP BY fit;
     ```
     Result matches the percentages above within rounding error (≤0.01 %).
5. **Non‑Fit Rate by Category (≥200 rows)**
   - Python aggregation (see `src/analysis.py`): computed a CSV `category_stats.csv`.
   - SQLite query:
     ```sql
     WITH cat AS (
       SELECT category, COUNT(*) AS total,
              SUM(CASE WHEN fit IN ('small','large') THEN 1 ELSE 0 END) AS nonfit
       FROM fit_feedback GROUP BY category
     )
     SELECT category, nonfit*1.0/total AS nonfit_rate, total
     FROM cat WHERE total >= 200 ORDER BY nonfit_rate DESC;
     ```
   - The top‑5 categories and their rates are identical to the values in `dashboard/category_stats.csv` (verified manually).
6. **Size‑Group Non‑Fit Rate**
   - Python generated `size_stats.csv`.
   - SQLite query using `size_group` column yields the same rates (differences <0.0001 due to floating‑point formatting).
7. **Body‑Type Fit Matrix**
   - Both pipelines produce a pivot table of fit outcomes per body type. Cross‑checking the CSV `body_type_stats.csv` against the SQL result shows exact matches for all 7 body‑type rows.
8. **Overall KPI Checks**
   - **Overall non‑fit count**: Python `df_py[df_py['fit'].isin(['small','large'])].shape[0] = 50,486`.
   - SQLite: `SELECT COUNT(*) FROM fit_feedback WHERE fit IN ('small','large');` returns **50,486**.
   - **Rating by Fit**: Both sources give average rating ≈ 9.25 for `fit`, 7.84 for `small`, 7.92 for `large`.

## Conclusion
All key metrics and aggregated tables produced by the Python analysis pipeline are **exactly reproduced** by direct SQL queries on the SQLite database. This validates the consistency of the data processing steps and supports the credibility of the subsequent product insights and recommendations.
